# GitHub Safe Push & Security Sanitation Protocol

> [!IMPORTANT]
> **ОБЯЗАТЕЛЬНОЕ ПРАВИЛО ДЛЯ КАЖДОГО ПУША:**
> Перед выполнением каждого `git push` агент или разработчик **ОБЯЗАН** заглянуть в этот скилл, провести аудит новых добавленных/измененных файлов и **дополнить данный скилл**, если в проекте появились новые конфиги, секреты, временные директории или архитектурные изменения, требующие защиты. Этот документ является живым реестром безопасности проекта.

## 1. Реестр чувствительных данных и файлов (Zero Leak Checklist)

Перед формированием коммита проверяется, что следующие файлы и шаблоны ни при каких условиях не попадают в систему контроля версий (контролируется через `.gitignore` и пре-коммит аудит):

### Категории секретов:
1. **Токены аутентификации:**
   - Персональные токены доступа GitHub (`ghp_...`, `github_pat_...`).
   - Claude Code / Vendor C OAuth2 токены (`.claude*/.credentials.json`, Windows Credential Manager dump).
   - Любые Bearer токены, API ключи Anthropic, OpenAI, Google Gemini.
2. **Файлы реальных конфигураций прокси:**
   - `config.json` и `instances.json` (содержащие реальные UUID, ключи Reality `pbk=...`, приватные WireGuard ключи).
   - `vendor_c_accounts.json` и `claude_accounts.json` (содержащие реальные email и аккаунты).
   - `.env` (содержащий мастер-пароль).
   - `instances/.instance_*.json` (и старые `.instance_*.json` в корне), `.vless2socks.lock`, `*.hbak` (шифрованные бэкапы).
3. **Логи и дампы сессий:**
   - `*.log`, `selftest-output.txt`.
   - Сессионные логи терминалов, пароли Xshell в незашифрованном виде.
   - Логи WSL GUI-лаунчеров `~/.claude-<id>/.local/state/claude-gui-<id>/launcher.log` и `main.log` Claude Desktop
     (`~/.claude-<id>/.config/Claude/logs/`): содержат вывод Electron, в т.ч. OAuth-URL входа с одноразовым
     `hop_nonce`, и выходные IP узлов. В документацию и скиллы переносить только обезличенные выдержки
     (без URL входа, nonce, реальных IP/хостов прокси-серверов) — см. `skills/claude_wsl_gui/SKILL.md`.
4. **Временные симлинки и бинарники:**
   - `proxys/link` и `proxys/lnk` (NTFS Junctions).
   - `bin/*.exe` (бинарник Xray-core загружается через `tools/get_xray.py`).
   - `dist/`, `build/`, `.venv/`.
   - `vless2socks.lnk` в корне (локальный ярлык с абсолютными путями машины).

## 2. Процедура безопасной передачи токена без утечки в `.git/config`

При использовании токена (например, Personal Access Token `ghp_...`) категорически запрещено:
1. Записывать токен в исходный код или скрипты репозитория.
2. Включать токен в текст сообщений коммитов (`git commit -m "..."`).
3. Сохранять токен в файле `.git/config` через команду `git remote set-url origin https://<TOKEN>@github.com/...` на постоянной основе.

### Рекомендуемый безопасный способ пуша:
Пуш выполняется через кратковременный вызов без сохранения учетных данных на диске, после чего remote URL немедленно возвращается к стандартному виду:

```powershell
# 1. Задание токена в переменной процесса в оперативной памяти (не сохраняется на диск)
$token = $env:GITHUB_PUSH_TOKEN # или передается в защищенном потоке

# 2. Формирование временного URL пуша
$repoUrl = "https://$($token)@github.com/captainmaclay/vless2socks.git"

# 3. Пуш в целевую ветку
git push $repoUrl HEAD:main --tags

# 4. Очистка переменной в памяти
$token = $null
$repoUrl = $null
```

Альтернативный способ через временный заголовок Git:
```powershell
git -c http.extraHeader="Authorization: Basic $([Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("x-access-token:$token")))" push origin HEAD:main
```

## 3. Пошаговый регламент перед каждым коммитом и пушем

Каждый раз перед отправкой изменений выполните следующие 5 шагов:

1. **Шаг 1: Проверка статуса и игнорируемых файлов**
   ```bash
   git status -u
   ```
   Убедитесь, что в списке Untracked файлов отсутствуют файлы с реальными паролями, ключами `.env` или личными сессиями.

2. **Шаг 2: Дифф-аудит изменений**
   ```bash
   git diff
   ```
   Внимательно просмотрите каждую измененную строку на предмет случайно оставленных ключей или тестовых токенов.

3. **Шаг 3: Проверка скиллов и тестов**
   Убедитесь, что все актуальные скиллы, документация и тесты включены в индексацию:
   - `skills/initial_start/`
   - `skills/xshell/`
   - `skills/github_safe_push/`
   - `setup_helpers/`
   - `tests/`

4. **Шаг 4: Актуализация данного скилла (`skills/github_safe_push/SKILL.md`)**
   Ответьте на вопросы:
   - *Добавились ли новые типы конфигов?* (Если да — внесите их в раздел 1).
   - *Появились ли новые вспомогательные скрипты?* (Внесите ссылки в `README.md`).

5. **Шаг 5: Формирование коммита и изолированный пуш**
   ```bash
   git add .
   git commit -m "feat: <осмысленное описание изменений>"
   # Выполнить пуш согласно разделу 2
   ```

## 4. Скрипт автоматизации безопасного пуша

Для минимизации риска человеческой ошибки в `setup_helpers/` включен скрипт [`git_safe_push.ps1`](file:///C:/proj/vless2socks/setup_helpers/git_safe_push.ps1), который в автоматическом режиме:
1. Сканирует индексируемые файлы на шаблоны секретов (регулярные выражения токенов, ключей, паролей).
2. Проверяет наличие `.env` и локальных аккаунтов.
3. Безопасно передает токен в процесс Git без сохранения в `.git/config`.
4. Сверяет статус ветки и выполняет пуш на GitHub.
